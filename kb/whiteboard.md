# Вайтборд-анимация: элементы прорисовываются с нуля

Проверено 2026-10-25 на EffectCraft 0.17.0. Проба лежит в `sandbox/whiteboard/`.

Задача: повторить ролик в стиле «рисованное объяснение». На сером фоне по очереди
появляются картинки и надписи, пока диктор говорит. Исходник — три кадра одной сцены
(`whiteboard-crypto_test/`, в git не попадает).

## Как сделано

1. **Нарезка на Python** (`sandbox/whiteboard/build_assets.py`, нужны numpy, Pillow, scipy):
   - фон: полином 4-й степени по (x, y), подогнанный по малонасыщенным пикселям кадра.
     Радиальный градиент с виньеткой он повторяет почти точно;
   - элементы: пиксели, отличающиеся от фона, разложены по прямоугольникам. Каждый
     пиксель достаётся первому элементу в списке, поэтому пересекающиеся рамки не
     дублируются;
   - то, что появилось во втором и третьем кадре, — разница между соседними кадрами;
   - на каждый элемент два PNG: цветной и только тёмный контур (`*_lines.png`).
   Если сложить всё обратно, получается исходный кадр: 99% пикселей отличаются не больше
   чем на 10 из 255.
2. **Сборка в EffectCraft** одним `run_script`: фон и по слою на элемент, у каждого Linear
   Wipe с ключами 100 → 0.
   - Картинка: сначала контур (wipe сверху вниз, feather 120), с перекрытием по времени
     цвет поверх (по диагонали, feather 160).
   - Текст: wipe слева направо, feather 25.
   - Значок «!»: Scale 0 → 115 → 100.
3. **Рендер:** `effectcraft-cli render --format h264` — 17 секунд 1080p за 14 секунд.

## Озвучка и синхрон по словам

Проверено 2026-10-25: edge-tts 7.3.1, голос `ru-RU-DmitryNeural`.

1. Текст взят из автосубтитров ролика (скилл `youtube-transcript`, дорожка `ru-orig`) и
   вычищен вручную: в автосубтитрах нет знаков препинания.
2. `sandbox/whiteboard/voice.py` озвучивает текст и сохраняет `voice.mp3`, `voice.srt`,
   `timing.json`. В тексте стоят метки `{turtle}`, `{buy}`. Скрипт берёт время слова,
   перед которым стоит метка (`boundary="WordBoundary"`).
3. В EffectCraft `voice.mp3` импортируется как обычный файл и кладётся слоем со
   `startTime = 0.6`. Ключи элементов считаются от `timing.json`.
4. `effectcraft-cli render --format h264 --audio on` даёт H.264 со звуком AAC. 30 секунд
   1080p рендерились 24 секунды. По `silencedetect` речь совпадает с метками до 0,15 с.

## v2: рисование пером (VectorCraft → EffectCraft)

Проверено 2026-10-25: VectorCraft 0.17.0, EffectCraft 0.17.0, SoundCraft 0.13.1.

1. Контур элемента — чёрные линии на белом PNG.
2. VectorCraft: `file.new` (размер элемента, Pixels) → `file.place {path, rect}` →
   `imageTrace.makeAndExpand {params: {mode: "blackAndWhite", fills: false, strokes: true,
   strokeWidth: 14, ignoreWhite: true, noise: 2}}` → `document.export {format: "svg"}` →
   `file.close`. Линии уже `strokeWidth` становятся штрихами по оси, широкие места —
   обводкой. 22 элемента = один `command_batch` из 111 шагов.
3. `sort_strokes.py`: составной путь режется по `M` на подпути, затем сортировка.
   **Trim Paths (Individually) рисует с ПОСЛЕДНЕГО пути в SVG**, поэтому порядок в
   файле обратный.
4. EffectCraft, в `run_script`:
   - `new File(path).read()` читает SVG (внутри папки проекта);
   - `app.run("edit.pasteSvg", {svg, name, comp})` вставляет его слоем-фигурой размером
     с viewBox. `app.run(id, params)` вызывает любую команду движка из скрипта;
   - штрихи утолщаются (`w*1.6+6`), чтобы маска закрывала линию с краями;
   - `root.addProperty("ADBE Vector Filter - Trim")`, `Trim Type = 2` (Individually),
     ключи End 0 → 100;
   - `layer.setTrackMatte(shape, TrackMatteType.ALPHA)` — работает.
   Под конец элемент проявляется целиком за 0,2 с: подчищает точки и куски, которые
   трассировка отбросила.
5. Рендер с масками и Trim Paths заметно медленнее: 1035 кадров за 214 с против 25 с.

## Ловушки

- **edge-tts нестабилен.** Тот же запрос то проходит, то падает с `NoAudioReceived`,
  причём параметры ни при чём. В `voice.py` до 8 повторов с паузой.
- Это онлайн-сервис Microsoft без официального API. Для коммерческого ролика лучше
  платный TTS с лицензией или свой записанный голос.

- **Направление Linear Wipe** как в After Effects: угол задаёт, *какая сторона скрывается
  первой*. 90° — левая, 0° — нижняя. Чтобы при ключах 100 → 0 проявлять слева направо,
  нужен угол 270°, сверху вниз — 0°, снизу вверх — 180°, из левого верхнего угла —
  315°.
- **`file.import` с именами вроде `text1.png`, `text2.png`** склеит их в
  последовательность кадров. Передавайте `sequence: false`.
- **Края элемента.** Если расширять альфу элемента, не заходите на пиксели соседних
  элементов: в рамку попал кусок красного крестика и проступил раньше времени.
- **`item.replace(new File(...))`** подменяет картинку другого размера, но точка привязки
  слоя остаётся старой. Задайте `Anchor Point = [w/2, h/2]` заново.
- `python -I` не видит пакеты из пользовательского site-packages (Pillow у нас стоит
  туда). Свои скрипты запускайте без `-I`.

## Что можно улучшить

- Рука с маркером, которая ведёт линию: нужна PNG руки, её Position привязывается
  выражением к фронту wipe.
- Настоящий штрих по траектории — Stroke (Reveal Original Image) по маске вдоль линии.
  Есть в 0.17.0, в этой пробе не проверялся.
- Для своих роликов удобнее рисовать элементы вектором (VectorCraft → SVG) и проявлять
  через Trim Paths: штрих идёт по настоящей линии, а не по прямой.
- Синхрон с голосом: метки слоя по тексту диктора или раскладка ключей по таймкодам из
  транскрипта.
